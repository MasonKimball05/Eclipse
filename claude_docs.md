# Eclipse — Documentation

**Author:** MasonKimball05
**Stack:** Python 3, PyQt6, QtWebEngine (Chromium), qtawesome

**Eclipse** is an Arc-inspired browser. It was called PythonBrowser at first (then, briefly, Halo). Since 27 Oct 2026 it's Eclipse underneath too: the bundle ID (`com.masonkimball.eclipse`), the data folder and the Keychain items. What had the old name is moved over the first time it's used. Arc is being wound down in favour of Dia, so this project carries its ideas forward: a vertical sidebar, Spaces, pinned and favorite tabs, a command bar in place of a new-tab page, and tabs that archive themselves.

---

## Running it

### As a Mac app (recommended)

```bash
./run.sh --build-app
```

This builds `/Applications/Eclipse.app`, in Finder's Applications folder, which you can open from Spotlight, Launchpad or the Dock like any other app. (An older `PythonBrowser.app` or `Halo.app` from before the rename, or an `Eclipse.app` left in `~/Applications` where it used to be built, goes to the Trash; it's only a launcher. Since the bundle ID changed to `com.masonkimball.eclipse` (27 Oct 2026), macOS sees a new app once: set it as the default browser again, and sites' camera and microphone access is asked for again.) Then choose **Eclipse menu → Set as Default Browser…**, and macOS asks you to confirm.

- **Links from other apps** (Slack, Mail, Messages…) open in a Little window, the same as Arc.
- **No rebuild needed for code changes:** the app is a small native launcher that runs this checkout with its virtualenv, so your next launch picks them up. Rebuild only if you move the checkout or Homebrew moves to a new Python version (3.15+). If you open an app whose checkout has moved, it says so ("Eclipse can't find its code") and how to rebuild, instead of quietly not starting.
- **Only one copy runs.** Opening it again, or running `./run.sh https://…`, hands the link to the window that's already open.
- **Signing:** the build signs the app with the best certificate of Eclipse's team (`verified.TEAM_ID`) on this Mac: a Developer ID Application one, else an Apple Development one, else ad hoc. A real certificate keeps the app the same app to the Keychain across rebuilds, so the key to your passwords doesn't ask again each time (an ad hoc app is a new app every build). Choose one yourself with `--sign "IDENTITY"`, or `--sign -` for ad hoc:

  ```bash
  ./run.sh --build-app --sign "Developer ID Application: Your Name (TEAMID)"
  ```

  This uses Apple's hardened runtime, with the exceptions a Python/Qt browser needs (loading the virtualenv's libraries, and run-time code for JavaScript and ctypes). Tested with an Apple Development certificate: the app runs and loads pages normally. To also notarize, save your credentials once with `xcrun notarytool store-credentials PROFILE --apple-id you@example.com --team-id TEAMID`, then add `--notarize PROFILE`. `--output FOLDER` builds elsewhere for testing; only the copy in /Applications registers as a browser with macOS.

**Eclipse Dev:** `./run.sh --build-app` builds `/Applications/Eclipse Dev.app`, a thin launcher around this checkout (code changes show up the next time it opens, no rebuild), with its own name, bundle ID (`com.masonkimball.eclipse.dev`) and an orange DEV mark on its icon, so it sits beside the signed `Eclipse.app` from `tools/release.py`. Both share one data folder (your Spaces, tabs and settings), so only one is open at a time: opening the other brings the open one forward. Either can be the default browser. Building Eclipse Dev never touches the signed Eclipse (only an old launcher-style `Eclipse.app` is retired to the Trash).


### The release app (to share)

```bash
./run.sh --release
```

This builds `dist/Eclipse.app`, `dist/Eclipse.dmg` (what people download: Eclipse beside an Applications shortcut to drag it onto, over a background drawn in the icon's colours, laid out by `dmgbuild` without touching Finder) and `dist/Eclipse.zip` (what updates download). Unlike `--build-app`, everything is inside it: its own Python, Qt and Qt WebEngine, and Eclipse's code. It runs without this checkout, and doesn't change when the checkout does. It's for **Macs with Apple silicon and macOS 13 or later** (PyQt's Qt is Apple-silicon only, and macOS 13 is the oldest it supports).

- **Built with python.org's Python:** set it up once with `tools/release_python.py`. It downloads python.org's installer (checking it's signed by the Python Software Foundation and notarized), unpacks it into `~/Library/Application Support/Eclipse Build/release-python/` without installing it, points its libraries at each other there instead of `/Library/Frameworks`, and makes a venv with Eclipse's requirements. `./run.sh --release` uses it from then on. Its OpenSSL comes with it, and its code is trimmed to Apple silicon. Without it the release is built with the development venv's Homebrew Python, which only runs on the macOS of the Mac that built it. Either way, the build works out the real minimum from the binaries and writes it into the app, so an older Mac says it needs a newer macOS rather than failing to start.

- **Signed with the Developer ID** ("Developer ID Application: Mason Kimball (F4P3T9JYP2)"), found in the Keychain by itself. Every library and Qt's helper app is signed from the inside out, with the hardened runtime and Apple's secure timestamp, as notarization requires. Library validation stays on: everything the app loads is signed by the team.
- **Sealed:** the Python is compiled ahead of time and Python is told never to write into the app, since one changed file breaks the signature. That's what lets **Settings → General** say **Verified** for this copy (once it's notarized), and **Not verified** for one that's been changed.
- **Notarizing:** save your Apple ID's notarization credentials once (they stay in your Keychain; make an app-specific password at appleid.apple.com first):

  ```bash
  xcrun notarytool store-credentials eclipse-notary --apple-id you@example.com --team-id F4P3T9JYP2
  ```

  Then `./run.sh --release --notarize eclipse-notary` sends the DMG to Apple (one round: its ticket covers the app inside), waits a few minutes, and staples the ticket into the DMG and the app, so both open without a warning on any Mac, even offline.
- `--install` also puts it in /Applications, in place of the development app. Both use the same data folder, so your Spaces, passwords and settings carry over. The first time, macOS asks whether the release may use the passwords' key (it's signed differently from the development app). Click Always Allow.
- **Versions:** each build is numbered by when it was made: version `2026.10.27`, build `202610271452` (what updates compare).
- **Publishing:** `./run.sh --release --notarize eclipse-notary --publish` also puts it on GitHub as a release (tag `release-<build>`, with `Eclipse.dmg` for people, `Eclipse.zip` for updates, and the commit subjects since the last one as its notes), through `gh`. It refuses a checkout with uncommitted changes or a commit that isn't pushed, so a release is always a commit anyone can look at. To publish the notarized build already in `dist/` without building it again, use `./run.sh --release --publish-built`: it checks the build is notarized and that its code is exactly the pushed commit's.
- **Updates:** a release copy checks GitHub's latest release soon after it opens (if it's been 6 hours) and every 6 hours after, and offers it in the **update window** (`update_window.py`): the new version and its size, the release's notes, and *Update & Restart* (it downloads right there, with a progress bar, then restarts), *Later*, or *Skip This Version* (not offered again by itself; Check Now still shows it). The download is checked by macOS before anything happens: signed by the maker's team (codesign, with the same requirement as Verified), notarized (spctl), Eclipse's bundle ID, and a newer build. Anything else is refused. After Eclipse quits, the new copy takes the old one's place (which goes back if that fails), and Eclipse opens again. Same team, same signature requirement, so the Keychain doesn't ask again. A copy macOS is running from Downloads (translocated) asks to be moved to Applications first. Code: `browser/release_update.py`.
- **Checked before signing:** the build runs the finished app's own Qt and Eclipse offscreen (no windows): every module imports, Qt WebEngine loads a page, and Python has macOS's trusted certificates for HTTPS (without them, python.org's Python can't verify any site, so updates couldn't connect: `net.py`). A build that wouldn't run stops there.
- How it's put together: `tools/release.py`. Python's own libraries from Homebrew (OpenSSL, SQLite, zstd, xz, mpdecimal) are copied into `Contents/Frameworks` with their paths rewritten to point there. Of Qt, only what Eclipse uses goes in: the Python modules it imports (`QT_MODULES`), the plugins they load (`QT_PLUGINS`), and the Qt libraries those link to, worked out from the links themselves. That leaves out Qt Quick 3D, Designer, multimedia and its FFmpeg, QML and the database drivers, about a quarter of the app.

### On Windows (early)

`run.bat` (double-click) or `.\run.ps1` does what `run.sh` does: a virtualenv in `%LOCALAPPDATA%\Eclipse Build\venv`, the requirements installed when they change, then Eclipse (`-Fresh`, `-Reset`, `-Tests` as on the Mac). Needs Python 3.14 from python.org. What's different there:
- **Secrets** (the keys for passwords, passkeys, the recovery PIN, My Apps tokens) go into **Windows Credential Manager** (`windows_vault.py`, used by `secure_store.py`), encrypted with your Windows sign-in. Windows doesn't ask before another of your programs reads them, as macOS's Keychain does.
- **Not there yet:** Touch ID's equivalent before filling a password (no prompt: Windows Hello would be the next step), importing from other browsers (their files are kept differently on Windows), the release app and updating itself (Windows copies update with `git pull`, through self_update.py's checkout updates), the traffic-light layout (Windows has its own title bar), and macOS's share sheet and Dock badge.
- **Keys:** shortcuts are written the Mac's way and `shortcuts.here()` binds them for Windows: ⌘ is Ctrl, the Control key's (⌃Tab, the private window's tab cycling) are Ctrl too, the Spaces are **Alt+1–9** (Ctrl+1–9 are the tabs, as in every browser; both on Ctrl would make Qt run neither), and the Library is **Ctrl+H** (Ctrl+Y is Redo there, in pages too). Text that names a key or a Mac thing goes through `shortcuts.for_here()` where it's shown (toasts, tooltips via `NativeTooltips` on the app, ⌘T rows' subtitles and badges, Settings rows and the shortcut list, What's New, a few labels): "⇧⌘T" reads "Ctrl+Shift+T", Finder File Explorer, the Keychain Credential Manager, this Mac this PC. An extension's suggested shortcut is its `windows` one there.
- **Also:** code and passwords use `theme.MONO_CSS` / `mono_font()` (Menlo, else Consolas: Qt has no generic monospace and would fall back to Segoe UI); updating relaunches through PowerShell (`self_update.relaunch_after`: no `/bin/sh`); device names (`CON`, `AUX`, `NUL`, `COM1`…) never become file names (`page_actions.not_reserved`); install hints say `winget install …` (`downloads.install_hint`); Windows' *Animation effects* off is Reduce Motion; and `run.bat` stays open on an error. `tests/test_windows.py` pretends to be Windows for all of these.
- **The crash check** asks Windows whether the last Eclipse is still running (`os.kill(pid, 0)` there would send it a Ctrl+C).
- **macOS is checked on every push too**, by the `macOS` workflow (`.github/workflows/macos.yml`) on GitHub's Apple-silicon runner: the same smoke check and unit tests, on a clean Mac with none of your apps or data. The live tests need a screen, so they stay local.
- **Checked on every push** by the `Windows` GitHub Actions workflow (`.github/workflows/windows.yml`): `tools/smoke.py` starts Eclipse offscreen, opens the window, loads a page and keeps a secret in Credential Manager; then the unit tests run (tests marked `mac`, needing macOS's own tools, are skipped).

### From the terminal

```bash
python3 -m venv venv
venv/bin/pip install -r requirements.txt
venv/bin/python main.py
```

> **Name the venv `venv`, not `.venv`.** Qt 6 won't load its macOS platform plugin from a path that contains a hidden (dot-prefixed) folder, and you'll get *"Could not find the Qt platform plugin 'cocoa'"*.

We moved from PyQt5 to PyQt6 because PyQtWebEngine for Qt 5 has no Apple Silicon build.

To try things without touching your real session, set a throwaway data folder:

```bash
ECLIPSE_DATA_DIR=/tmp/pybrowser-test venv/bin/python main.py
```

Your session, favicons, cookies and cache normally live in `~/Library/Application Support/MasonKimball05/Eclipse/`. A folder from before the rename (`…/MasonKimball05/PythonBrowser`) is moved there the first time Eclipse starts, and its old cache is dropped. The Keychain items are **Eclipse Vault**; one still under **PythonBrowser Vault** is moved the first time it's read (macOS asks once, since the app's bundle ID changed). The venvs live in `~/Library/Application Support/Eclipse Build/` (moved from `…/PythonBrowser` by `run.sh`).

## The Arc model

| Concept | What it does |
|---|---|
| **Favorites** | The icon grid at the top of the sidebar. Every Space shares them. |
| **Spaces** | Separate sets of tabs, each with its own name, colour and emoji. The whole window takes on the Space's colour. |
| **Sharing a Space** | Right-click a Space → *Share Space…* (or *Spaces → Share This Space…*) makes a small `Name.eclipse-space` file and opens macOS's share menu for it: AirDrop, Messages, Mail. Someone with Eclipse opens it (double-click, drag it onto the Dock icon, or *Spaces → Import Space…*) and, after saying yes, gets a new Space with its name, icon, colours, look and pinned tabs in their folders; a feed Live Folder comes along as its feed. Only addresses and names are shared: not Today's tabs, the profile, sign-ins, where you'd scrolled, notes, or GitHub folders (they're your own pull requests). Everything read from a shared file is checked: only `http`/`https` addresses, names cut to length without control or direction characters, real colours, at most 500 tabs and 6 folders deep, files up to 2 MB. Code: `browser/space_share.py`; the app tells macOS it opens these files (`com.masonkimball.eclipse.space`, in `tools/build_app.info_plist`). |
| **Sync** | *Settings → General → Sync with your other Macs and PCs* (off until you turn it on) keeps your Spaces (name, icon, colours, look, order), their pinned tabs and folders, and your Favorites the same on each computer it's on, through iCloud Drive: no account and no server. Today's tabs stay on each computer, as in Arc. Each device writes its own file in iCloud Drive's `Eclipse Sync` folder (written whole, then swapped in, so another never reads half of one) and reads the others' every 20 seconds. A Space at a time (and Favorites, and the order) is compared: the device that changed it last wins, and a deletion is a change. So different Spaces changed on two Macs both stay; the same Space changed on both before they've synced keeps the later change. Tabs that stay keep their open pages; ones unpinned elsewhere close; a new tab with the id of one of your Today tabs gets its own. Turning it on when another computer already syncs asks: *Use (that computer)'s* Spaces here (yours go into a backup), or *Keep Both*. Before it first changes anything each time Eclipse opens, it saves a backup in the data folder's `sync backups` (the last five; File → Restore from Backup…). Quitting sends this Mac's last changes without taking any. Other devices' files are checked like a shared Space's (web addresses only, names cut to length, real colours), every Live Folder that reads an address too (a JSON, page or calendar folder never reads `file://`), and a file that's broken or nested too deep is skipped without stopping the others. A Repos folder or a JSON folder with a token that arrives (or changes) through Sync doesn't run git or send the token until you choose *Use on This Computer…* in its menu (see Live Folders' tokens below). Windows uses iCloud for Windows' `iCloudDrive` folder. Code: `browser/sync.py` (the merging is plain data, tested as two Macs in `tests/test_sync.py`). |
| **Pinned tabs** | Tabs kept above the divider. Each one remembers its home URL. Closing one only *unloads* it (the `—` button). |
| **Dark websites** | *Settings → General → Dark websites* darkens pages that only come in light (Chromium recolours the page; images stay as they are), straight away and without reloading. Pages with a dark look of their own stay as they are. Leave a site light with *Dark Pages on …* in the shield menu. |
| **Keeping your place** | A tab remembers how far down its page you'd scrolled. When it wakes from sleep, or comes back after you quit and reopen the browser, it reloads to the same spot. |
| **Today tabs** | Tabs below the divider. New tabs go on top. They're archived after 12 hours unused (you can change this from the archive button). Rows slide in when a tab opens, slide out when one closes (the ones below glide up), and *Clear* sweeps them away top to bottom (with **Undo** in the message that follows, for five seconds: everything comes back where it was, folders and all); folders opening and closing do the same. |
| **Start view** | With no tab open (the last one closed, an empty Space), the page area keeps the Space's own background, as in Arc, with a little to start from: the Space's name, a search pill that opens ⌘T, your **most visited** sites as tiles (one per site, ranked the way ⌘T ranks history: visits, weighted to recent ones, and named after the site: "Gmail", not "Inbox (3)"), and **recently closed** tabs to bring back in a click. Each Space can turn it off for the plain emptiness (`Space.start_view`; `None` follows *Settings → Tabs → Start view*, the default) (`start_view.py`). |
| **Command bar** | ⌘T or ⌘L. One box for URLs, searches, open tabs, history, archived tabs and app commands. ↑ and ↓ move the highlight, which glides between rows. VoiceOver reads each result's title, and its address or kind. |
| **Pages you've read** | A few seconds after a page loads, its readable text goes into a full-text index on this Mac (`pages.db`, SQLite FTS5; the newest 5,000 pages). Typing in ⌘T shows pages whose text matches, with the words around your match and when you read it (*Read Oct 3 · …*). Never kept: private windows, sign-in pages, non-web pages, and excluded sites: yours (the shield menu's *Keep … Out of Page Search*, or *Settings → Privacy → Excluded Sites…*) and, from the start, banks, health records and mail (`page_index.DEFAULT_SKIP`; `mail.*` is any site's mail). Removing one there lets its pages in; pages already kept from a site that's excluded go at the next launch. **Ask Claude About Pages You've Read** (a ⌘T row under Ask Claude, for a question of a couple of words or more) finds the five pages that best match its words (any of them), gives Claude the parts around them, and links its [1], [2] citations to those pages, listed under the answer with when you read each. Only those pages are linked: a link the answer writes itself keeps its words, not its address. Clearing history clears the index; Settings → Privacy turns it off or clears it. Code: `browser/page_index.py` (the asking is `claude_feature.ask_pages`); tests in `tests/test_page_index.py` and `tests/test_privacy_features.py`. |
| **Watch This Page** | Right-click a tab → *Watch for Changes…* (or ⌘T → "Watch This Page for Changes") and choose how often (15 minutes to a day; 30 minutes unless you say), or select part of a page, right-click it → *Watch This* to watch just that part (kept as a CSS selector for its element, from the nearest unique id, and the text it had: if the page moves things about, the deepest element that still starts the same way). Due pages are loaded one at a time in a hidden page on your default profile (your logins), muted, given 3 seconds to settle, and read in an isolated world; an error waits twice as long each time, up to a day, until one works. What's compared is the text without the noise (`page_watch.normalise`: whitespace, dates, times, "3 minutes ago", counters like "1,204 views"), so only a real change counts; it keeps the before and after and tells you as a site's notification would (`notify.NotificationCenter.present`: a banner, the Dock bouncing, and the "•" on the site's tab until you look), with Claude's one-line summary when Claude is on, or a plain one (`diff_summary`: "“$299” → “$249”", "Added: …"). Watches are in the settings (`page_watches`); *Settings → Watched Pages* changes how often, pauses, shows the last change (*Changes…*: before and after, line by line) or removes them. Code: `browser/page_watch.py`; tests in `tests/test_page_watch.py`. |
| **Little window** | Arc's "Little Arc": links from other apps, page popups, or ⌥⌘N open in a compact window, fading in as it rises into place (and fading out as it closes). It has a slim header tinted with your Space theme, the site's name (click it or press ⌘L to edit the address), back/reload/copy-link buttons, and **Open** (⌘O), which moves the live page into the main window as a Today tab. To send outside links to a new tab instead, use *File → Open Links from Other Apps In*. |

With VoiceOver, every tab, folder, Favorite and sidebar button reads out its name (and a tab what its badges say: unread, playing sound, sleeping). Drag tabs between Favorites, Pinned and Today to reorganise them: the tab lifts out of its place and the other rows part to show where it will land (drop on the middle of a folder to put it inside). Right-click a tab or Space for more options. Swipe sideways with two fingers on the sidebar to switch Spaces.

### The welcome, and importing from other browsers

On a first launch (not in a throwaway profile: tests and `--fresh`) a **welcome** lists the browsers on this Mac and what each can bring: Arc's Spaces and tabs, Chrome's (and Brave's, Edge's, Vivaldi's, Chromium's) bookmarks and history, each one's saved passwords (macOS asks about that browser's key first), and Safari's bookmarks. Nothing comes over unless it's ticked. Then it offers to make Eclipse the default browser and to pick the Space's colour. Any time later: **File → Import from Another Browser…** or ⌘T.

- **Bookmarks** (`browser_import.py`) become a Space per browser (per profile, if it has more than one): the bookmarks bar as pinned tabs, its folders as folders, the rest in a folder after them. Importing again replaces that Space. **History** (the latest 5,000 pages, with visit counts) goes into ⌘T's suggestions.
- **Safari** keeps its bookmarks where macOS wants Full Disk Access first, so the welcome takes the file Safari exports instead (**File → Export → Bookmarks…**; Firefox's and Chrome's exported files work too). With Full Disk Access granted it reads Safari's own, history included. Safari's passwords come through the Passwords app's export (Settings → Passwords & Passkeys → Import).

### Importing from Arc

**File → Import from Arc…** (or Arc in the welcome) reads Arc's local data in `~/Library/Application Support/Arc`, read-only:

- **Brought across:** Spaces (with name, emoji and colour), pinned tabs including nested folders, Favorites, Today tabs, your last 5,000 history entries (used for ⌘T suggestions) and site icons. Also:
  - **Settings** Eclipse has too (from `~/Library/Preferences/company.thebrowser.Browser.plist`): how long before tabs archive, whether links from other apps open in a Little window, and tidier download names and pinned-tab titles.
  - **Archived tabs** (`StorableArchiveItems.json`): the latest 300 (as many as Eclipse keeps), in Library → Archived Tabs. Arc's times count from 2001.
  - **Air Traffic Control rules** (`StorableLinkRouting.json`) that send a site to a particular Space. Arc's "whichever Space is open" rules have no equivalent here, so they're left out.
  - **Profiles:** a Space on one of Arc's own profiles (not Default) gets an Eclipse profile named like it ("School Stuff" → `school-stuff`), so it keeps its own sign-ins apart. It starts empty: Arc's cookies can't be copied.
- **Offered once if it was missed:** the welcome only appears on a first launch with no data at all. If Eclipse has been opened before (from source, say) but still has only its empty starter Spaces, and Arc is on the Mac, it asks about Arc once, a moment after opening (`arc_import_offered` in settings).
- **Not brought across:** logins and cookies, which are encrypted with Arc's own key, so you'll sign in again. Extensions are imported separately: *Settings → Extensions → Add Extension → Import from Arc* (see Extensions & userscripts below).
- **Importing again** replaces the Spaces you imported last time instead of duplicating them.

**Folders** only live in Pinned:
- Click a folder to open or close it.
- Drop a tab onto the middle of a folder to put it inside.
- Right-click for Rename, Ungroup or Delete.
- Right-click a tab and choose *Move to Folder* to file it.

### More Arc features

| Feature | How to use it |
|---|---|
| **Your cards** | The first page of Settings, named after you (as Arc's was): your **Eclipse card**, a little membership card with your name, a made-up title (*Shuffle* for another), a shape and colours you choose, the day you started using Eclipse, and a stamp for each year since. Below it, if you had one, your **Arc card**, just as it was in Arc (name, title, colours, shape and the day you joined). It's copied out of Arc as soon as Eclipse starts, into Eclipse's settings and into `arc-card.json` in its data folder, so it stays after Arc deletes its data. Either card copies or saves as an image. Only the card file and the name and join date from Arc's account file are read, never its sign-in tokens or email. |
| **Editing a Space** | Click the Space's name at the top of its tabs, or right-click it or its icon in the switcher. A popover lets you rename it, pick an icon (line icons or emoji), choose a colour, switch its profile, open the theme editor, add a folder or delete the Space. Every change applies immediately. |
| **Space themes** | Right-click a Space and choose *Edit Theme…*. Pick up to 3 colours for a gradient, set the intensity, choose light/dark/auto, and add optional grain. Changes preview live. |
| **Split View** | Choose *Tabs → Split View…* (⌃⇧=), drag a tab from the sidebar onto the page, or right-click a tab and choose *Open in Split View*. Up to 4 panes. Click a pane to focus it; hover a pane and click × to take it out, or press ⌃⇧- to separate. Panes settle in with a short crossfade. |
| **Peek** | Links that open a new tab from a pinned tab or favorite float in a card instead, rising into place as the page behind dims (and sinking away when closed). Press Esc or click outside to close it, or use ⤢ to keep it as a tab. Turn it off with the "Turn Peek On / Off" command in ⌘T. |
| **Resizing the sidebar** | Drag its right edge, which highlights on hover. Double-click the edge to reset it. The width is kept between 190 and 420 pt and remembered. |
| **Light and dark** | When macOS switches between light and dark, the window crossfades into its new colours. Settings, the Library, Downloads and What's New fade in as they open, and ⌘F's find bar slides down into place (and back up). Hovering a tab, folder or New Tab row fades its highlight in and out, as in Arc. |
| **Hidden sidebar** | After ⌘S hides it, touch the left edge of the window and the sidebar slides out over the page. It stays while the pointer is anywhere between the edge and just past the sidebar (or one of its menus is open), slides back a moment after you move away, and turns round smoothly if you come back on its way out. While the sidebar's hidden the page has the whole window; the traffic lights come out with the sidebar, inside it. With no tab open (the last one closed, or an empty Space) it comes out by itself and stays, since there's nothing to hide it for, and goes back to coming and going once a tab opens. |
| **Boosts** | Use the *Boosts* menu, then *Boost This Site…*, to add your own CSS and JavaScript for a site. *Zap Elements* lets you click things on the page to hide them for good; press Esc when done. Only Zap's own clicks count (the page can't add rules of its own), and only plain selectors are kept. |
| **Notes** | ⇧⌘N (*File → New Note*). A note is a tab with a text editor, saved as Markdown in your data folder. ⌘B / ⌘I / ⌘U format text. Typed shorthand, as in Apple Notes: "* " or "- " starts a list, "[] " a checklist (click a box to tick it, or ⇧⌘L), and "# ", "## " or "### " a heading. Return on an empty list item ends the list, and the line after a heading is ordinary text again. |
| **Easels** | *File → New Easel* (or ⌘T → "New Easel") opens a whiteboard tab: text, sticky notes, drawing, rectangles, ellipses and arrows in six colours (shortcuts V T S P R O A), plus images you paste or drop in. ⌘-scroll or pinch to zoom, ⌘0 fits everything, ⌘Z / ⇧⌘Z undo and redo, Backspace deletes. ⌘B / ⌘I / ⌘U make text bold, italic or underlined: the words you've selected while writing, or whole texts and sticky notes that are selected. Right-click anything for *Duplicate*, *Bring to Front* (⇧⌘]), *Send to Back* (⇧⌘[) and *Delete* (and *Open Page* on a capture). Select one thing and drag a corner handle to resize it: pictures and text keep their shape (text by changing its size; ⇧ keeps any shape), and the opposite corner stays put. ### How it feels

- **Hover:** buttons, tiles and rows all light up under the pointer, with a hint of the Space's colour. In the sidebar the highlight fades in and out, as in Arc.
- **Motion:** the sidebar slides away and back (⌘S) and slides out from the edge when hidden, the command bar settles into place as the page dims, the sidebar slides between Spaces, and toasts, notification banners and permission cards fade in and out. Everything is under a quarter of a second. With *Reduce motion* on in macOS's Accessibility settings, things just appear.
- **Type:** SF Pro, the Mac's own font, as in Arc: Medium weight for the sidebar's tabs, folders and address, and for ⌘T's results (Arc's own fonts in its app bundle, such as Inter, are only for Boosts).
- **Controls:** on/off settings are macOS-style switches, and sliders match them, in your Space's colour (system blue for grey Spaces). Scrollbars stay hidden until you scroll or point at them.
- **Site icons:** an icon that would vanish against the sidebar (GitHub's all-white one on a light Space, an all-black one on a dark Space) gets a small contrasting tile.
- **Empty page:** with nothing open, the page area is just a faint shade of your Space's colours, like Arc, so the sidebar stands apart: no page, nothing in the way. ⌘T opens something.

- **A narrow sidebar:** the Space buttons in the bottom bar share the room there is (full size when it fits; smaller and closer together, down to 18pt with 12pt icons, when it doesn't; and with too many even then, a page of them shows (1–3, 4–6…), the one with your Space on it: `Sidebar._fit_switcher`). Swipe sideways over the Space buttons (or scroll a mouse wheel there) for the next or last page, without switching Space; the buttons go the way your fingers do. Anywhere else on the sidebar, a swipe still switches Space. The buttons' tooltips say how many more there are. Favorites take as many columns as fit (up to four). The search pill's placeholder becomes "Search…" rather than half a sentence, and only a site's address is cut from the left.
- **Opening or closing a folder** redoes only its own list, leaving its rows still there as they are (`MainWindow.toggle_folder`, `TabSection.set_tabs(refresh=False)`), and a list moves only the rows not already in place. Rebuilding the whole sidebar (every Favorite and Space button made again, every row taken out and put back) cost its first frames: measured 35–45 ms before, 12–20 ms after. Favorites and the Space buttons are only made again when they've changed, which makes every sidebar update quicker.
- **Google's sign-in** (`accounts.google.com`, `accounts.youtube.com`) is told Eclipse is Firefox, in the User-Agent header and in what its scripts can read (`site_quirks.py`): otherwise it refuses with "This browser or app may not be secure", going by signs that Eclipse is built on an engine inside an app. Every other site, Google's own included, sees Eclipse as it is.
- **Folders** open and close as one block: their rows grow in (or shrink away) together in one box (`RowReveal` with several rows), one height change a frame, so even a big folder glides. The rows in the box sit as far apart as the list puts them (its 2pt spacing too): without that they were a few points short and jumped into place as the animation ended, the jitter seen in a screen recording (28 Oct 2026). When it ends, the box comes out of the list before its rows go back in, and the list is laid out there and then (the other way round, for a frame both took up room and everything below dropped a block's height). The animation's clock starts after the first frame is drawn, and a folder's rows don't drift as they go (only a single row does, as Arc's Clear). The box's size takes in the list's 2pt gap after it too (`RowReveal._size`): a box with no height still had its gap, so as a folder finished closing the rows below jumped up 2pt after everything else had stopped; for its last point the box is out of the list instead. Two more, found by grabbing every frame of a close: the list packs its rows at the top (`AlignTop`: while a folder closes it's for a moment taller than its rows, and spread over that room the folder's own row bounced), and after a change it's laid out at once with the sidebar re-measuring it first (`TabSection._lay_out_now`): otherwise the first frame of a close had the list at its closed height, everything in it drawn on top of each other. Before, each row had its own animation and a folder of 8 juddered (and one of 9 or more just popped open).
- **Switching Spaces slides with the sidebar floating too** (the hidden sidebar come out, or kept out with no tab open): the cover is then the sidebar's own card rather than the window round the page. It used to skip the slide there and jump straight to the Space. The new Space's picture is taken again just before the cover fades (`SpaceSlide.lift`), so the fade never shows the sidebar twice, a few points apart.
- **A new page on a dark Space** is blank in the page area's dark colour, not Chromium's white, until it's about to draw its first frame (a tiny script in every page, `eclipse-painted` in `webview.harden`, says so; a page in the background, which doesn't draw, goes back 0.6 s after it's loaded) (`MainWindow._dark_until_painted`): switching to a Space whose tab had no page yet (each one the first time, or a sleeping one) flashed white for half a second or more.
- **Dragging a tab** always cleans up after itself (`sidebar.start_drag`'s `finally`): the page area's drop zone (which takes clicks, to take a dropped tab) going away and the sidebar's rebuilds resuming. A drag that failed half-way (clicking a tab quickly while switching) left the page not taking clicks, and folders not opening, until a restart. Should the zone ever be left up anyway, the first click on it puts it away.

### Settings, shortcuts & Library

- **Settings** (⌘,, or *Eclipse → Settings…*) has a search box at the top ("sleep", "cookie", "qwen"): pages without a match step aside and matching settings light up; Return scrolls to the first. It has one page each for:
  - **General:** default browser, where outside links open, search engine (Google, DuckDuckGo, Bing, Brave, Kagi or Ecosia), and spell check (off until you turn it on; the first time, it downloads your language's dictionary, a few hundred KB, from Chrome's dictionary server).

### Ad blocking

Built in, so it works without an extension. It works in three layers:
- **Network:** third-party requests to ad and tracker domains are cancelled before they leave the browser. The domains come from Peter Lowe's list and the StevenBlack hosts list (about 70,000 domains), refreshed weekly. Requests to the site you're on are never blocked, which keeps sites working.
- **Cosmetic:** a few CSS rules hide the empty boxes ads leave behind.

**Videos wait for a click** (*Settings → Privacy & Ad Blocking*): video and sound don't start by themselves anywhere, private windows too, until you click them. Qt has one switch for all media, so muted background videos wait as well. Off by default.
- **YouTube:** its ads come from the same servers as the videos, so a small script skips them instead (it clicks Skip, or jumps to the end).

The shield in the URL pill shows how many requests were blocked on the current site. Click it to allow ads on that site or turn blocking off.

### Extensions & userscripts

Qt WebEngine's own extension support crashes on macOS, so Eclipse has its **own lightweight runtime** (`browser/ext/`). Manage everything in **Settings → Extensions**. The puzzle piece in the URL pill lists your extensions (click one for its popup); *Pin to URL Bar* in that menu gives an extension its own button, with its badge. Keyboard shortcuts from an extension's manifest work too (⌘⇧X opens Proton Pass), unless they'd take over one of the browser's.

**Installing:** on a Chrome Web Store extension page, click **Add to Eclipse** (bottom right). Before anything is installed you see what it can access and anything that won't work here. Extensions and userscripts installed from the web are **checked for updates daily** (or *Check for Updates* in Settings); an update that asks for more permissions asks you first.

**Userscripts** (Greasemonkey/Tampermonkey format):
- Open any `.user.js` link (e.g. Greasy Fork's Install button) and an install dialog shows where the script runs and what it can use. You can also add one from a link or file, or write a new one.
- Supported: `@match`/`@include`/`@exclude`, `@run-at`, `@require` (downloaded at install), `@noframes`, and `GM_getValue/setValue/deleteValue/listValues`, `GM_addStyle`, `GM_xmlhttpRequest` (cross-site, made from Python), `GM_openInTab`, `GM_setClipboard`, `GM_notification`, `GM.*` promise versions, `unsafeWindow`.
- Scripts with `@grant none` run in the page like Tampermonkey; scripts using GM APIs each run in an isolated world of their own, which neither the page nor other scripts can reach.

**Chrome extensions** — install from a Chrome Web Store link (or while on the store page), a `.crx`/`.zip`, an unpacked folder, or import from Arc. Files are served from `pbext://<id>/`.
- Works: content scripts and CSS (`run_at`, `all_frames`, `MAIN` world), messages from websites the extension lists in `externally_connectable` (`onMessageExternal`, which is how Proton Pass signs in), `chrome.storage` (local/sync/session, with `onChanged`), `runtime.sendMessage`/`onMessage` with replies, long-lived ports (`runtime.connect`, `tabs.connect`, `onConnect`), `tabs.*` (query, create, update, remove, sendMessage, events), `i18n`, toolbar popups with badges, options pages, background pages and MV3 service workers (run as hidden pages, with `importScripts`), `scripting.executeScript`/`insertCSS` (including `world: "MAIN"` and `allFrames`), offscreen documents, `contextMenus` (in the page's right-click menu), `commands`, `alarms`, `notifications`, `downloads.download`, and cross-site `fetch` from extension pages.
- **Native messaging** (`runtime.connectNative`, `sendNativeMessage`): extensions can talk to helper programs on this Mac, found the way Chrome finds them: registered in a `NativeMessagingHosts` folder (Chrome's, Chromium's, Arc's, Edge's, Brave's, or our own data folder), and only for extensions the helper lists in `allowed_origins`. Exits are noted on stderr (`[extensions] native helper … exited`).
- **Blocking rules (`declarativeNetRequest`)** run in the browser's request interceptor: static rulesets, dynamic and session rules, block / allow / allowAllRequests / redirect / upgradeScheme, and request-header changes. Rules are indexed by domain and keyword, so an ad blocker's 200,000 rules load in under a second (on a background thread) in about 20 MB and cost a fraction of a millisecond per request. When an extension's rule decides a request, the built-in blocker leaves it alone.
- Approximated: `webNavigation` (from tab updates, no per-frame detail). `webRequest` can **watch** requests (`onBeforeRequest`, `onBeforeSendHeaders`, `onSendHeaders`, with URL/type/tab filters) but not block or change them from a listener, because Qt won't pause a request; the response-side events never fire (Qt 6.11 has no response hook).
- Present but inert, so code that touches them doesn't crash: blocking `webRequest`, `sidePanel`, `tabGroups`, `cookies`, `identity`, `nativeMessaging` and similar. Extensions that rely on these are marked "may not work fully". Response-header rules can't be applied (Qt doesn't allow it).
- **Isolation:** each extension's content scripts run in their own JavaScript world, separate from the page and from other extensions. Qt only allows its web channel in one world per page, so these worlds call Python with console messages stamped with a secret per-world token, and get answers by Python running code in that world. Websites can't call the runtime at all.
- What this means for the Arc five:
  - **Pie Adblock blocks** with its own rules (ads blocked, trackers swapped for harmless stand-ins, cookie banners blocked).
  - **Proton Pass** loads cleanly: its popup, its autofill dropdown inside pages, and the account.proton.me sign-in handoff all work as far as can be tested without signing in. Try signing in.
  - **Video Downloader** can now see requests, but it decides what's a video from response headers, which Qt can't show it. The built-in yt-dlp downloader covers this.
  - **iCloud Passwords** starts Apple's Passwords helper over native messaging, but **macOS kills the helper on launch** ("Launch Constraint Violation", SIGKILL): Apple only lets it run for browsers that pass its signing rules. Tested 23 Oct 2026 by launching PythonBrowser.app normally: killed when signed ad hoc, signed with an Apple Development certificate, and signed with that certificate plus the hardened runtime. Arc, a notarized Developer ID app, gets through. Next to try once the Developer ID certificate exists: `./run.sh --build-app --sign "Developer ID Application: …"`, then with `--notarize` if that's not enough (or Apple may only allow certain browsers). When this happens the browser says so in a toast.
  - **Claude** needs the debugger and side panel. It can now reach Claude Code's own native host, but its panel can't appear.
- Changes apply to pages loaded afterwards.

### Downloads & yt-dlp

A download a page starts can be **paused and resumed** from its row in Downloads (⌥⌘L): the button beside Cancel. yt-dlp's video downloads can only be cancelled.

**File → Downloads** (⌥⌘L) lists every download. Drag a finished one straight into Finder, Mail or Messages (it's the file itself), or double-click it to open it.

**Download Video…** (⇧⌘D, or right-click a tab) works like this:
1. Paste a link; it's prefilled with the current page.
2. yt-dlp describes it: title, available qualities, subtitles, or playlist size.
3. Choose video or audio, the format, quality, subtitles and folder.

**Download Settings** (the gear) sets your defaults: save folder, file-name template, format and quality, subtitle languages, cookies from another browser, and a speed limit. Regular browser downloads use the same save folder.

Every download (from a page or yt-dlp) gets macOS's quarantine mark, as Safari and Chrome do, so opening an app, script or installer from one goes through Gatekeeper's check first. A downloaded .html file opened in Eclipse can't read other files on your Mac.

It needs `brew install yt-dlp ffmpeg`. The format choices are ported from Custom-Mac-Media-Player: MP4 prefers H.264 + AAC so it plays everywhere.

### Claude features (Arc Max, without an API key)

- Starting the CLI takes about 8 seconds. To hide that, one `claude -p` process is kept **warm**, already started and waiting for input. Answers begin in under a second.
- Each process answers one request (a fresh context every time) and is then replaced.
- Web pages are untrusted, so the CLI runs with **all tools disabled** (`--tools ""`), no MCP servers, no settings or CLAUDE.md files, and from a neutral folder. The worst a malicious page can do is make an answer wrong.

### Passwords

Eclipse keeps your passwords, encrypted, and fills them in. Everything's in **Settings → Passwords & Passkeys**.

- **Saving:** sign in somewhere and a card offers **Save your password for github.com?** (or **Update…** when it changed), with **Never for This Site**. A sign-in that asks for the username on a page of its own (Google's, Microsoft's) saves it with the password from the next page.
- **Strong passwords:** making an account, a card offers one (three groups of six, like Apple's Passwords); **Use Strong Password** fills it in, password and confirm both, and it's saved when you send the form.
- **Filling:** on a sign-in page, a card offers your accounts for that site. Picking one asks for **Touch ID or your Mac's password** first: once each time Eclipse opens, or every time (your choice). Nothing is ever filled by itself. A site only gets its own passwords, or its own subdomains' (accounts.google.com's on google.com, never one github.io site's on another), and never on a page sent in the clear (http).
- **Sign-in forms in a frame** (a sign-in box embedded in the page) are filled and saved too, when the frame is the same site as the page (accounts.example.com's inside example.com). A frame from another site, like an ad, is never offered a password. The frame's address comes from Eclipse's script, which the page can't touch, and filling runs in that frame alone.
- **Importing:** **Import ▾ → From Arc…** (or Chrome, Brave, Edge, Vivaldi, Chromium: whichever are on this Mac with saved passwords) reads that browser's saved passwords directly. They all keep them the same way, encrypted with a key in the Keychain; macOS asks whether Eclipse may use it, so click Allow. **From a File…** takes the CSV that Apple's Passwords app exports (File → Export All Passwords), or Chrome's, Firefox's or Bitwarden's. Afterwards Eclipse offers to move that file to the Trash, since it holds every password as plain text.
- **Verification codes** (two-factor): a login can keep its setup key, the secret behind a site's QR code. Apple's and Bitwarden's exports bring theirs along (the OTPAuth column), and **Edit** takes one: the key under the QR code, or an `otpauth://` link. On a page asking for the code, a card offers to fill it in after Touch ID (a single field, or a row of one-digit boxes), and **Code** in the list copies it. The codes are the standard 30-second ones (RFC 6238), made on this Mac. Importing a file again adds codes to logins you already have.
- **Breached passwords:** **Check** (after Touch ID) asks Have I Been Pwned whether any saved password has turned up in a known data breach, and flags those in the list ("in a data breach", first). Only the first 5 characters of each password's SHA-1 hash are sent; the service answers with every breached hash starting with them, padded with made-up ones so even the answer's size says nothing, and the match is found on this Mac. It's the one password feature that goes online, and only when you click it.
- **Exporting:** **Export…** asks for Touch ID, warns that the file is plain text, and saves a CSV in Apple's Passwords layout (with verification codes), which Passwords, Chrome and Eclipse all import. Only your account can read the file.
- **Seeing them:** **Show…** asks for Touch ID, then lists them, with search. **Copy** clears the clipboard a minute later. **Edit** changes one (with **Suggest a Strong One**), **Add…** saves one by hand. The list points out passwords **reused** on more than one site and ones **easy to guess**, worked out on this Mac (nothing's sent anywhere).

**How they're kept safe:** `passwords/logins.json` is encrypted (AES-256-GCM) with a random key, and the key isn't in the data folder. It's in the macOS Keychain, written through Apple's Security framework (`secure_store.py`) so that the Keychain trusts only Eclipse with it: any other program asking gets macOS's prompt, which you can refuse. That's the trouble Chrome had: its key could be read by any program, so stealing passwords meant copying two files. (Items made with the `security` command trust that command, so any program can read them silently: none of Eclipse's secrets use it any more. App tokens from older versions are moved into Eclipse's own items the first time they're read.) The files in `passwords/` and `passkeys/`, and `recovery.json`, can only be read by your account. The page script that notices forms and fills them runs in a world of its own that the page can't see. Its messages go straight to the browser, never to the console, and carry a token made fresh each launch, so a page can't pretend to be it.

**Recovery PIN** (shared with passkeys, `recovery.py`): with one set, a copy of the passwords' key, sealed with the PIN, goes into backups with the encrypted passwords, so the PIN brings them back on another Mac.

Until Eclipse is a signed release, "Eclipse" to the Keychain is the program running it (the app, or Python from a checkout). A rebuilt app is new to it, so the first use after a rebuild asks once.

### Addresses

**Settings → Addresses** keeps your name, company, email, phone and address (as many as you like, each with a label such as Home or Work). On a form that asks for at least three such things (a checkout, a sign-up; not a newsletter's lone email box, and never a sign-in form), clicking into one of its fields brings up a card offering your saved addresses. Picking one fills the form's **empty** fields (anything you've typed is left alone), splitting the name for first and last name fields and the street for two-line addresses, and picking from country dropdowns. Fields are recognised by the `autocomplete` names sites are meant to use, or else by their names. Like passwords, the page script runs where the page can't see it, a page learns nothing until you pick an address, and its messages never reach the console. Kept in `addresses.json` in the data folder, readable only by your account (`addresses.py`).

### Passkeys and security keys

**Eclipse keeps passkeys itself**, as Chrome does in Google Password Manager. When a site offers to make one, a card asks **Save a passkey for github.com?**. Eclipse then checks it's you with **Touch ID or your Mac's password**, and saves it. Next time the site asks, the card lists your accounts there; pick one, confirm it's you, and you're in. Sites see Eclipse as a browser with passkeys of its own, so they offer to make them. Buttons on these cards wait a moment before they can be clicked, so a page can't slip one under a click meant for something else.

- **Where they're kept:** each passkey's private key is in the macOS **Keychain**, where only Eclipse can read it; which site and account it's for is in `passkeys/` in the data folder. Signing happens in the browser, for the page's real address (as Qt reports it), so a page can only ever use its own site's passkeys.
- **Recovery PIN** (Settings → Passwords & Passkeys, shared with passwords): set one (at least 8 characters) and a copy of every passkey, locked with the PIN, goes into your backups. On another Mac, or after reinstalling, restore the backup and **Recover…** with the PIN. Nobody can open that copy without the PIN, and there's no server limiting guesses, which is why it's longer than Chrome's 6 digits.
- **iCloud Keychain:** Settings → Passwords & Passkeys has the switch, off for now. macOS lets only a signed browser (with a Developer ID and Apple's browser permission) make passkeys in iCloud Keychain. Once Eclipse is a signed release, new passkeys can go there, and ones Eclipse kept can move over with macOS's passkey import.
- **Security keys** (a YubiKey or similar, over USB) work too: **Use a Security Key** on the card, or when a site asks for one. The card says to plug it in and touch it, asks for its PIN (or a new one, typed twice), lets you pick the account, or explains what went wrong, with Try Again.
- **Passkey autofill**: a sign-in page that waits in the background for a passkey (GitHub's does) gets a quiet card, **Sign in to github.com with your passkey?**, but only if Eclipse has one for the site; otherwise nothing shows. **Not Now** puts the card away.
- A site that asks outright when you have no passkey there gets a card saying so, with how to get one: sign in another way, then add a passkey in the site's settings, and Eclipse offers to save it.

How it works: `passkey_store.py` makes passkeys and signs with them (P-256, through the `cryptography` package) and keeps the recovery copy (scrypt, then AES-256-GCM). `passkeys.py` has the cards, and a small script in each page, in the page's own world, which hands every passkey request to the browser first. The browser answers it with one of Eclipse's passkeys, passes it on to Chromium for a security key (whose steps Qt hands back as `webAuthUxRequested`), or refuses it. The Touch ID and password check is LocalAuthentication, through `macos.verify_owner`.

### Verified builds

Eclipse is open source (MIT): anyone can build and change their own copy. **Settings → General** says what this copy is:

- **Verified**: a release, signed with Eclipse's maker's Developer ID, notarized by Apple, and unchanged since. macOS checks every file in the app against its signature, so a single changed file means it's no longer verified.
- **Built from source**: it runs from source code (a checkout, or the app `./run.sh --build-app` makes, which runs the checkout's code). Nothing wrong with it; it just isn't a signed release.
- **Not verified**: it's unsigned, signed by someone else, not notarized, or changed since it was signed.

The answer comes from macOS's own tools, not from Eclipse. Anyone can also check from Terminal: `spctl -a -vv /Applications/Eclipse.app` names who signed it. It turns on once `verified.TEAM_ID` holds the maker's Apple Developer team ID and releases ship as a signed app with Eclipse's code inside it.

### What a web page can't do

Pages are kept to their own business. What stops them, and where (reviewed 28 Oct 2026; `tests/test_security.py` and the live tests check it):

- **YouTube's ads:** besides skipping an ad that plays (now every 0.1 s, muted, jumped to its end or played at 16×), a script in the page's own world takes `adPlacements`, `adSlots`, `playerAds` and `adBreakHeartbeatParams` out of a video's details before YouTube's player reads them (`ytInitialPlayerResponse`, `JSON.parse`, `Response.json`), as uBlock Origin does, so no ads are planned; feed, banner and overlay ads are hidden with CSS. In `adblock.py` (`YOUTUBE_PRUNER`, `YOUTUBE_CSS`); off for YouTube if it's an allowed site. YouTube changes often: if ads come back, the keys are what to check first.
- **Windows:** a page can't open a pop-up by itself, at load or from a timer (`JavascriptCanOpenWindows` off in `webview.harden`, every profile). After a click, `window.open()` still works, for sign-in pop-ups. Nor can it open your notes, easels, an extension's own pages or `file://` addresses as a new window (`window.handle_new_window`).
- **Full screen:** only the page you're looking at can go full screen, a toast says *host is full screen. Press Esc to leave.* every time, and Esc always leaves, so a page can't pass off a drawing of a browser or a password box as the real thing.
- **The address:** a long address is cut from the left in the URL pill, so the end (whose site it is) always shows: `…login.evil.example`, never `accounts.google.com.lo…`. After *Visit Anyway* on a certificate warning, the pill shows a red warning instead of the lock for that site, for the rest of the session.
- **Downloads:** a file that can run something on your Mac (an app, even zipped or in a `.tar`, `.tbz`, `.xip` or `.cpgz`, a script, an installer, a screen saver, `.webloc`, `.mobileconfig`) or on Windows (`.exe`, `.scr`, `.com`, `.vbs`, `.hta`, `.msix`, `.reg`, `.url`, and `.js`/`.wsf` there only; `downloads.RISKY`, `WINDOWS_RISKY`) asks before it's saved. So does a page's second download within 8 seconds, so it can't fill your Downloads folder. Pages that aren't in a tab or window (Browse for Me's and Live Folders' readers) can't download at all. Everything downloaded gets macOS's quarantine flag, so Gatekeeper checks it before it opens, and on Windows the Mark of the Web (a `Zone.Identifier` stream, `downloads.mark_downloaded`), so SmartScreen and Office's Protected View do. Claude's tidier names can't carry characters that change how a name reads (a right-to-left override turning `fdp.command` into `dmmoc.pdf`), and never make a file something that runs (`README` renamed `Read Me.command`): such a name is left alone (`tidy_downloads.new_path`).
- **Autofill:** passwords and verification codes are filled only after a click on the card and Touch ID, then only if the page (or frame) is still the login's site. Addresses are filled only into fields you can actually see (not off the side, see-through, a few pixels wide or invisible), and only in the form you clicked (or, with no form, the part of the page around that field). Passwords and passkeys for a site never go to another site under a shared suffix (`passkey_store.PUBLIC_SUFFIXES`: countries' `co.uk`-style suffixes, and hosting where every customer gets a name, like `github.io`, `neocities.org`, `myshopify.com`, `ngrok.io`). That's a hand-kept list, not the whole Public Suffix List.
- **Passkey requests** carry a token only the browser's own script knows, so a frame inside a page (an ad) can't make a passkey request look like the page's.
- **Page text in Eclipse's own windows** (titles in tooltips and toasts, a video's title, a site's name in Reader, userscript update prompts) is always shown as text, never as HTML, so a title like `<b>accounts.google.com</b><!--` can't redraw a prompt. Links in Ask on Page answers open only if they're web links.
- **Extensions:** an extension's own runtime files are never served to websites, and MV3 `web_accessible_resources` are only served to the sites their `matches` name. `GM_xmlhttpRequest` and extensions' cross-site fetches only reach `http`/`https`, never `file://`.
- **Restoring a backup** says how many extensions, userscripts and apps-for-extensions it has, and offers *Restore Without Extensions* (the ones you have stay). A backup from someone else could carry any of them.
- **Feeds** over 8 MB are stopped rather than read into memory.
- **Left as they are:** Air Traffic Control's domain rules match whole labels anywhere in the host (so `docs.google` works), which means `zoom.us` also matches `zoom.us.example.com`; it only chooses which Space a link from another app opens in. The extension channel's move to the page's main world before a `pbext:` navigation commits is gated by `page.url()` on every call.

### Troubleshooting slow pages

- **Pages (GitHub especially) take 15–30 s or never finish**, while `curl` gets them in a second: the
  network has IPv6 routes that go nowhere (on 23 Oct 2026 the Mac's IPv6 default routes went through VPN
  tunnels, utun0–2, with no IPv6 on Wi-Fi). Chromium tries IPv6 first and waits on each attempt before
  falling back to IPv4. Check with `curl -6 https://github.githubassets.com` (it times out). Fix it in
  the VPN (Tailscale: turn off its IPv6 route / exit-node IPv6) or set Wi-Fi's IPv6 to *Link-local only*
  in System Settings → Network → Wi-Fi → Details → TCP/IP.
- **Pages load slowly while the browser is behind other windows**: macOS App Nap. The browser now holds
  off App Nap while anything is loading (`macos.busy`), which roughly halved load times in testing.

### How the pieces talk

- Widgets never mutate data. They call `MainWindow` methods (`activate_tab`, `move_tab`, `close_tab` …).
- `MainWindow` changes the `Store`. The Store emits `structure_changed`, and the sidebar is rebuilt once per event-loop pass.
- Per-tab updates (title, favicon, URL) go out through `Tab.changed`. Each sidebar row listens to its own tab, so nothing is rebuilt.
- Web views are **lazy**. A restored or pinned tab gets no Chromium page until you click it.
- Features talk to the core through hooks (`browser/features.py` lists them all). The window sends them out with `emit(hook, …)`, collects what they add with `gather(hook, …)` (menus, ⌘T commands, Settings pages, sidebar buttons), and takes the first answer with `first(hook, …)`. `window.feature("claude")` gets one feature, or None when it isn't there, so the core checks before using one.

### Ideas for next steps

- **Extensions, next steps:** Qt's native extension support still crashes (retested 23 Oct 2026, Qt 6.11.2 and 6.12.0, in `QtWebEngineCore::ExtensionManager`), hence our own runtime. Worth adding to it: response-side `webRequest` events if a future PyQt exposes Qt's response interceptor, and per-frame ids for `webNavigation`/`frameIds`.
- **Video codecs:** PyQt's Qt WebEngine is built without H.264/AAC (patent-encumbered), so MP4-only videos don't play; YouTube and most big sites use VP9/AV1 and work. Fixing it means building Qt WebEngine from source with `-webengine-proprietary-codecs` (hours of compiling).
- **Live Folders:** more sources that need signing in (Gmail, Slack), or GitHub searches through `gh`.
